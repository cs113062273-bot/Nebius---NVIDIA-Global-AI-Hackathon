# Benchmark methodology

Three separate denominators must never be merged into a model repair score.

1. **Reference replays:** seven synthetic multi-step applications, sharing two principal seeded defect families (dialog focus management and mouse-only custom actions). An author-provided patch is applied through the same bounded patch/verifier pipeline. This tests execution, source bounds and evidence, not autonomous diagnosis.
2. **Negative controls:** two source-patch runs (cosmetic-only, wrong functional outcome) plus 14 in-memory verifier mutations based on real passing browser evidence. These are labeled separately in results. A rejection on selected controls is not proof that all false positives are eliminated.
3. **Focused pairs:** 12 browser assertion families × ten visible-label variants, 120 broken/reference pairs. Variants include multilingual strings and changed text; correlation is explicit. These are not 120 independent real bugs, repairs or users. Coverage includes Enter/Space, naming, checkbox, tabs, disclosure, dialog entry/escape/restoration, status semantics, motion and reflow.

The historical fixture pins a11y-dialog broken parent and human repair commits, includes exact upstream sources/licenses and deterministic TypeScript stripping/CJS-to-ESM adaptation. The harness tests a dialog hidden by opacity (a plausible animation condition) whose focus restoration was intercepted by still-active focus listeners. It replays the same frozen Escape/restoration journey on both revisions. This is a **nonblind reproduction with a published human fix**, not an unseen model repair. The earlier empty-dialog candidate did not reproduce in this Chromium environment and is retained as an excluded candidate; it must not be counted as a recovered bug.

Each run records environment, version, content hashes, per-action evidence and failure category. p50/p95 use nearest-rank quantiles over seven reference pipeline wall times; they include browser startup/cleanup and are not inference latency. Functional-regression-free recovery means the independent pointer oracle passed before and after; it is not a claim about every unlisted behavior. No live model call, model token usage, routing experiment or historical autonomous-recovery rate exists yet. No genuinely unseen holdout has been evaluated, so holdout count is zero.

`npm run benchmark` writes `benchmarks/results.json` and full local evidence under `artifacts/benchmark/`. `node scripts/historical.js` reruns the pinned case offline. Source acquisition can be reproduced using `node scripts/fetch-historical.js --restore`; this downloads exact revisions, never third-party package install scripts. Only verified source content and licenses are included. Final audit states the numbers actually observed.
